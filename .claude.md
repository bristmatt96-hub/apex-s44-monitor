# Macro Credit Monitor — Claude Code Context

## What This System Is

AI-augmented European credit analysis and trading platform. Monitors 200 iTraxx Europe Series 44 constituents (125 Main + 75 Crossover) for credit deterioration signals, then identifies equity put opportunities where credit stress hasn't yet repriced into equity options. The core alpha is the **gap score**: credit signal strength minus equity repricing.

## Critical Files — The Alpha Engine (Module 2: Equity Bridge)

These 3 files ARE the strategy. Read them before touching anything:

| File | Lines | Purpose |
|------|-------|---------|
| `analytics/signal_scorer.py` | 509 | Computes credit_signal_score (0-100), equity_repricing_score (0-100), and gap_score. 7 credit dimensions + 4 equity dimensions |
| `analytics/trade_structurer.py` | 435 | Decision tree: catalyst type × IV percentile × gap strength → OTM_PUT, ATM_PUT_SPREAD, STRADDLE, CALENDAR_PUT, FAR_OTM_PUT, or SKIP |
| `analytics/credit_equity_bridge.py` | 689 | Orchestrator — loads credit data, fetches live equity from yfinance (15-min cache), runs scorer + structurer, returns ranked opportunities |

### Signal Scorer Components

**Credit Signal Score** (7 dimensions, weighted):
- Spread level (20%) — absolute CDS spread → implied PD
- Spread momentum (15%) — widening/tightening trend
- RV composite (15%) — relative value vs peers
- Filing severity (15%) — restructuring, downgrade filings
- Maturity wall (15%) — refinancing risk
- Conviction direction (10%) — analyst sentiment
- Sector contagion (10%) — industry-level stress

**Equity Repricing Score** (4 dimensions):
- 5-day price change (30%), 20-day price change (20%), IV percentile (30%), put/call ratio (20%)

**Gap Score** = credit_signal_score - equity_repricing_score
- STRONG (>50), MODERATE (30-50), WEAK (10-30), NONE (<10)

### Trade Structurer Decision Tree

| Gap Signal | IV Percentile | Recommended Structure |
|------------|---------------|----------------------|
| STRONG | < 25th | OTM_PUT (cheap vol, buy it) |
| STRONG | 25-50th | ATM_PUT_SPREAD |
| STRONG | 50-75th | CALENDAR_PUT or STRADDLE |
| STRONG | > 75th | FAR_OTM_PUT (expensive vol, go cheap) |
| MODERATE | any | Narrower spreads or MONITOR |
| WEAK/NONE | any | SKIP |

## Pitch Deck Manifest — Keeping the Deck in Sync

`deck/deck_manifest.json` is read by the pitch deck generator to produce PowerPoint for pod shop meetings. **Keep it updated whenever you build, change, or complete a feature.**

### When to Update

1. **Complete a feature** — move from `in_progress` to `live`, add `since` date
2. **Start building something new** — add to `in_progress` with status
3. **Change system stats** — companies monitored, data sources, filing types
4. **Add infrastructure** — new VPS, API connection, database tables
5. **Deprecate something** — remove from `live` or mark deprecated

### Rules

1. Always update `_LAST_UPDATED` when changing anything
2. Be honest — only put things in `live` that are actually running
3. Use clear status values: `planned`, `building`, `testing`, `exploring`, `not started`
4. Keep descriptions concise — one sentence each for description and detail
5. Never delete the `spread_snapshot` section — updated separately with market data
