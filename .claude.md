# Macro Credit Monitor — Claude Code Context

## What This System Is

AI-augmented European credit relative value platform. Monitors 200 iTraxx Europe Series 44 constituents (125 Main + 75 Crossover) for tradeable dislocations across CDS, bonds, and tranches.

**Strategy**: Long/short CDS, bond-CDS basis, delta-hedged tranches (primarily 0-3% equity tranche). The system enables relative value selection across the full 200-name universe — what to be long, what to be short, and when basis or tranche convexity offers better expression.

**AI edge**: Decentralized AI (Bittensor subnets) for speed — be first to receive relevant information (filings, news, equity moves +/-2%, documentation risk like Ardagh/Altice France situations) so positions can be adjusted quickly. The LLM determines relevance, filtering noise from actionable signal across all 200 names simultaneously.

**Pitch philosophy**: Heavy on analysis, risk, and process. Show current examples with comprehensive risk analysis of each strategy. Demonstrate how AI augments an experienced PM's edge by helping see "everything" — not marketing, but substance.

## Pitch Deck Manifest — Keeping the Deck in Sync

`deck/deck_manifest.json` is read by the pitch deck generator to produce PowerPoint for pod shop meetings. **Keep it updated whenever you build, change, or complete a feature.**

### When to Update

1. **Complete a feature** — move from `in_progress` to `live`, add `since` date
2. **Start building something new** — add to `in_progress` with status
3. **Change system stats** — companies monitored, data sources, filing types
4. **Add infrastructure** — new VPS, API connection, database tables
5. **Deprecate something** — remove from `live` or mark deprecated

### Rules

1. Always update `_LAST_UPDATED` when changing anything
2. Be honest — only put things in `live` that are actually running
3. Use clear status values: `planned`, `building`, `testing`, `exploring`, `not started`
4. Keep descriptions concise — one sentence each for description and detail
5. Never delete the `spread_snapshot` section — updated separately with market data
