## Pitch Deck Manifest — Keeping the Deck in Sync

### What This Is

There is a file called `deck_manifest.json` in the project root. This file is read by a separate pitch deck generator (managed in Claude.ai conversations) that produces a PowerPoint deck for pod shop meetings. The manifest describes what this system can actually do — so the deck is always honest.

**You (Claude Code) are responsible for keeping this file up to date whenever you build, change, or complete a feature.**

### Where It Lives

```
/Users/matt/projects/credit-catalyst/deck_manifest.json
```

### When to Update It

Update `deck_manifest.json` whenever you:

1. **Complete a feature** — move it from `in_progress` to `live`, add a `since` date
2. **Start building something new** — add it to `in_progress` with a status
3. **Change system stats** — companies monitored count, new data sources, new filing types
4. **Add infrastructure** — new VPS, new API connection, new database tables
5. **Deprecate or remove something** — remove from `live` or mark as deprecated

### How the Manifest is Structured

```json
{
  "_LAST_UPDATED": "2026-02-22",         // ← UPDATE THIS EVERY TIME

  "system_status": {
    "companies_monitored": 200,           // ← actual count
    "index": "iTraxx Europe Series 44",
    "sec_filers_covered": 14,             // ← how many file with SEC
    "european_filers_covered": 0,         // ← how many EU filers we cover
    ...
  },

  "capabilities": {
    "live": [                             // ← THINGS THAT ARE RUNNING
      {
        "name": "SEC Filing Monitor",
        "description": "...",
        "detail": "...",
        "since": "2025-12"               // ← when it went live
      }
    ],
    "in_progress": [                      // ← THINGS BEING BUILT
      {
        "name": "FCA/European Filing Monitor",
        "description": "...",
        "status": "planned"               // ← planned / building / testing
      }
    ],
    "future": [                           // ← LONGER-TERM ROADMAP
      {
        "name": "IBKR API Integration",
        "description": "...",
        "status": "not started"
      }
    ]
  },

  "spread_snapshot": { ... }              // ← updated separately with market data
}
```

### Rules

1. **Always update `_LAST_UPDATED`** when you change anything
2. **Be honest** — only put things in `live` that are actually running and working
3. **Use clear status values**: `planned`, `building`, `testing`, `exploring`, `not started`
4. **Keep descriptions concise** — one sentence for description, one for detail
5. **Never delete the spread_snapshot section** — that's updated separately with market data
6. **If Matt asks you to update the manifest**, do it as part of the current task, not as a separate step

### What Happens Next

When Matt wants a fresh pitch deck:
1. He uploads `deck_manifest.json` to Claude.ai
2. Claude.ai regenerates the PowerPoint from the manifest
3. The tech slides automatically reflect whatever you've built

This means the pitch deck is always truthful — it shows exactly what this system can do today.
