# Credit Catalyst — Project Context for Claude Code

## What This Project Is

A credit analysis system that identifies mispriced credits in iTraxx Europe Main (125 names) and Crossover (75 names), outputs long/short/flat CDS recommendations, and analyses index tranches. Delivered via web dashboard (mobile-responsive), Excel reports, and Telegram alerts.

**No trade execution. No crypto. No equity options.**

Every output the system produces serves dual purpose: (1) operational credit analysis and (2) pitch evidence for multi-manager hedge fund platforms (Millennium, Citadel, Verition, etc.).

## Core Data Models (Define These First)

Every downstream component — dashboard, Excel, pitch deck, idea sheets — consumes these models. Get them right early.

```python
# core/models.py

class CreditAssessment:
    """Output of the Analyst agent for a single name"""
    entity_name: str              # e.g. "Ardagh Group"
    itraxx_index: str             # "Main" or "Xover"
    current_spread: float         # Current 5Y CDS spread in bps
    fair_spread: float            # Model fair value spread
    direction: str                # "LONG_RISK" / "SHORT_RISK" / "FLAT"
    conviction: int               # 1-5 scale
    signal_sources: list[str]     # Which monitors triggered this
    thesis: str                   # 2-3 sentence thesis
    catalyst: str                 # Specific, time-bound catalyst
    key_risks: list[str]         # What could go wrong
    fundamental_metrics: dict     # leverage, coverage, FCF, etc.
    updated_at: datetime

class TradeIdea:
    """A specific actionable trade recommendation"""
    assessment: CreditAssessment
    instrument: str               # "5Y CDS" / "Xover 0-3% tranche" etc.
    entry_spread: float           # Target entry level
    stop_loss_spread: float       # Stop loss level  
    notional: float               # Suggested notional
    position_size_pct: float      # As % of total book
    hedge: str | None             # Hedge description if applicable
    scenario_pnl: dict            # {"bull": X, "base": Y, "bear": Z}
    risk_metrics: dict            # DV01, CS01, JTD, spread_var
    
class RiskSnapshot:
    """Portfolio-level risk at a point in time"""
    timestamp: datetime
    gross_exposure: float
    net_exposure: float
    sector_concentration: dict
    rating_buckets: dict          # {"BB": X%, "B": Y%, "CCC": Z%}
    spread_duration: float
    top_5_positions: list[dict]
    stress_tests: dict            # 8 scenario P&Ls
    current_drawdown: float
    max_drawdown_30d: float
    correlation_matrix: dict

class TradeJournalEntry:
    """Captures every trade for track record and case studies"""
    trade_id: str
    idea: TradeIdea
    entry_date: datetime
    entry_spread: float
    exit_date: datetime | None
    exit_spread: float | None
    pnl_bps: float | None
    pnl_usd: float | None
    signal_source: str            # Which alpha source triggered
    strategy_type: str            # "relative_value" / "catalyst" / "regime"
    outcome: str | None           # "win" / "loss" / "open"
    post_mortem: str | None       # What happened, lessons learned
```

## The 3 Agents

### The Analyst (`agents/analyst.py`)
- Input: Raw data from monitors (filings, ratings, spreads, sentiment)
- Context: 471 knowledge chunks from ingested books
- Output: `CreditAssessment` per name
- Every assessment auto-saved to trade journal database
- Runs on demand (triggered by monitor alerts) and on schedule (daily full universe scan)

### The Strategist (`agents/strategist.py`)  
- Input: All current `CreditAssessment` objects + macro regime + correlation data
- Output: Portfolio-level recommendations, `RiskSnapshot`, relative value rankings
- Identifies: best longs, best shorts, tranche opportunities, hedges needed
- Outputs risk reports matching multi-manager platform format

### The Briefer (`agents/briefing.py`)
- Input: Latest assessments, risk snapshot, market data changes, alert log
- Output: Morning brief (Telegram + PDF), real-time alerts, weekly digest
- Every brief saved as PDF — doubles as process evidence for platform pitches

## Alpha Sources (Priority Order)

1. **European Regulatory Filing Speed** — Scrape RNS/DGAP/AMF, process with Claude API in <60 seconds. Bloomberg has 5-30 min delay on many filings.
2. **Credit-Specific Earnings NLP** — Whisper transcription + Claude analysis tuned for credit language (covenant headroom, refinancing, leverage path). Different from equity sentiment.
3. **Social Sentiment for Thin Credit Markets** — Bittensor SN13 Gravity API for Twitter/Reddit scraping of the 200 names. Credit markets are less covered than equity.
4. **Rating Action Prediction** — Track CreditWatch placements, measure time-to-action, cross-reference with fundamental deterioration.
5. **Knowledge Base** — 471 chunks of credit analysis wisdom used as Claude API context. Genuine differentiator in how the system reasons.

## Pitch Output Requirements

The system must produce these artefacts, auto-generated from live data:

### Idea Sheet (one per trade)
One-page PDF: Thesis | Catalyst (time-bound) | Structure (instrument, sizing) | Risk Metrics (DV01, CS01, JTD) | Scenario P&L (bull/base/bear) | Stop Loss | Hedge

### Risk Report (weekly)
Excel workbook: Gross/net exposure | Sector concentration | Rating buckets | Duration/spread duration | Correlation matrix | 8 stress scenarios | Drawdown timeline | Position-level risk contribution

### Trade Journal (ongoing)
Database table: Every recommendation logged with thesis, entry, signal source, exit, P&L, post-mortem, tagged by strategy type and outcome

### Backtest Report (on demand)
PDF + Excel: Monthly returns | Cumulative P&L | Sharpe, Sortino, max DD | Win rate by signal type | Attribution by alpha source | Benchmark comparison (iTraxx Xover TR, EUR HY index)

### Pitch Deck (auto-generated PowerPoint)
15-20 slides: Strategy overview | Edge description (3 types: information, analytical, structural) | 3-5 live ideas | Risk framework | Backtest + attribution | Case studies (wins AND losses) | Technology demo

### Morning Brief (daily)
Telegram + PDF: Market overview | Top 5 credit ideas | Regime assessment | Material changes overnight | Active alerts

## Key Technical Decisions

- **Backend**: FastAPI (Python) — already have analytics in Python
- **Frontend**: Next.js with Tailwind — mobile-responsive
- **Database**: PostgreSQL — trade journal, assessments, risk snapshots
- **AI**: Claude API (Anthropic) with knowledge base chunks as system context
- **Excel**: openpyxl for report generation
- **PowerPoint**: python-pptx for pitch deck generation
- **PDF**: WeasyPrint or reportlab for idea sheets and briefs
- **Alerts**: Telegram Bot API
- **CDS Pricing**: ISDA standard model (bakera1/CreditDefaultSwapPricer or QuantLib)
- **Data**: FinancialReports.eu API, Finnhub, Bittensor SN13 Gravity API, direct RNS/DGAP scraping

## What NOT to Build

- Trade execution (no IB Gateway, no broker connection)

- Equity options analysis
- Forex analysis
